## 3. AI 产物中的问题与调整

| 问题 | 发现和修正 |
| --- | --- |
| 匿名填写与免登录填写的含义混淆，文档也曾把“允许匿名”写得过于笼统 | 填写者必须先登录；问卷允许匿名且本次选择匿名时才不写 `userId`，未选择匿名时仍保留用户 ID |
| 文本、数字填空与三类业务题型的术语不够统一 | 前端改用填空主类型及文本/数字子类型。作业要求“至少”三类；历史技术枚举的数量本身不是功能违规，后端继续兼容旧表示 |
| 按选项显示文字手工填写跳转条件容易出错 | 改成通过界面选择选项，数据库保存稳定的选项 ID |
| 大量原始填空内容进入聚合结果可能超过 BSON 大小限制 | 统计汇总仍由 MongoDB 聚合，原始填空答案改为独立分页查询 |
| AI 或历史文档的测试结论与最新代码不一定一致 | 以实际本机执行结果核对。2026-10-17 的首次集成测试因 MongoDB 未启动失败；修复后测试通过 |
| Chromium E2E 首次运行缺少 Playwright | 执行 `npm install`、安装 Chromium 后重新执行，7/7 通过（含父测试） |
| 统一的 1 MiB JSON 上限可能拒绝满足单题业务限制的长答卷 | 本轮将答卷提交接口提高到 16 MiB，其他 JSON 接口保持 1 MiB，超限明确返回 413；补充整卷容量与超限回归 |
| 旧答卷缺少去重标记时，仅有部分唯一索引不足以恢复历史账号的防重能力 | 本轮对有明确 `userId` 的历史答卷执行幂等去重标记回填，保留原回答；无法识别账号的匿名历史记录不猜测身份；补充兼容回归 |
| 报告对 `answered`、新填空写入和测试结果的说明不够精确 | 按代码说明空答案及数字 0 的统计口径、前端统一表示与 API 兼容范围；测试表加入可复算的固定数据，本轮与历史结果分开记录 |
