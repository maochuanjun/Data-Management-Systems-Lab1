## 2. AI 输出存在的问题及处理

1. **匿名含义曾被误读。** 早期实现倾向于允许未登录用户匿名填写，后来按需求改为“先登录，提交时可选择匿名”，并在服务端保留按账号去重能力。
2. **初始实现存在边界缺陷。** 曾出现保存期间覆盖新输入、不可满足的必答题、特殊 JavaScript 对象键导致答案丢失、统计聚合超过 16 MiB 等问题。通过专门复现与回归测试修复，没有仅依赖 AI 对代码正确性的描述。
3. **页面及文档逐渐偏离课程重点。** 曾累积大量学习笔记、过程性审查报告和重复说明。本轮以数据库设计、后端逻辑、测试和交付文档为主线收敛。
4. **统计概览查询成本偏高。** 本轮增加汇总模式，旧 API 保持兼容；新增场景在真实 MongoDB 集成测试通过。浏览器 E2E 首次断言执行过早，修复测试等待时序后独立 E2E 和完整验收均通过。

## 3. 人工决策和 AI 贡献的区分

已有开发日志表明：需求边界、技术栈、测试整理与扩展性要求由使用者提出；大部分实现、缺陷修复和测试代码由 AI 编写或修改。因此不将 AI 产物记作人工逐行手写。人工审查应重点确认真实需求、能够解释集合设计与跳转路径、检查测试输出，并在提交前独立复核代码与报告。
