# 测试用例与结果

测试围绕问卷创建、逐题填写、结果统计和题目复用展开。第二阶段继续执行第一阶段用例，并增加版本、共享、题库和跨问卷统计测试，用于检查扩展后的系统能否保留原有功能和数据。测试步骤、代表输入、预期输出及已执行结果集中说明如下，测试代码均在仓库的 `tests/` 中。

## 一、测试组织

| 层次 | 位置与工具 | 检查内容 |
| --- | --- | --- |
| 领域与 HTTP 单元测试 | `tests/unit/`，Go `testing` | 配置、题型约束、跳转、整卷路径、题目内容比较、请求体上限；需要时替换存储边界。 |
| 数据库集成测试 | `tests/integration/`，真实 MongoDB 与 HTTP 服务 | 持久化、索引、身份与权限、并发、历史数据兼容、聚合和分页。 |
| 前端交互测试 | `tests/frontend/frontend.test.cjs`，Node.js 与模拟 DOM | 输入、按钮状态、分支草稿、未保存提醒以及受控异步响应。此层不等同于真实浏览器。 |
| 浏览器端到端测试 | `tests/e2e/`，Playwright 与 Chromium | 通过页面执行问卷、题目、版本和题库操作，连接真实 HTTP 服务与 MongoDB。 |

集成和浏览器测试使用随机命名的独立数据库，结束时清理自己的测试数据。下表中的“通过”对应第六节列明的执行日期与范围；没有把最新一次前端复跑写成全套测试重新执行。

### T06 的固定输入与统计口径

以下检查发生在三份初始答卷保存后、后续并发提交开始前。“跳过”表示没有提交对应答案字段。

| 填写账号 | q1 单选 | q2 多选 | q3 数字 | q4 文本 |
| --- | --- | --- | --- | --- |
| alice | a | 跳过 | 20 | 跳过 |
| bob | b | x、y | 跳过 | 中文🙂 |
| charlie | b | x | 10 | 中文 |

预期与断言一致：`totalResponses=3`；q1 的 a、b、end 分别为 1、2、0；q2 的 x、y、z 分别为 2、1、0。q1–q4 的 `answered` 分别为 3、2、2、2；q3 平均值为 `(20+10)/2=15`。指定 `questionId=q3` 后只返回 q3，整卷提交数仍为 3；用 `limit=1` 读取两页，分别得到 20 和 10。

`TestStatsPaginationAndSummaries` 另检查空值定义：缺失字段和 `null` 不计回答数，合法空文本、空数组计入，数字 0 参与平均值。该用例中的数字 1、3、5、0 得到平均值 2.25。`TestMultipleChoiceExactCount` 将最少和最多选择数同时设为 2，验证一个、三个或重复 ID 失败，两个不同选项通过。

### 跨问卷固定数据

| 数据来源 | 提交值 | 本人统计的贡献 |
| --- | --- | --- |
| 本人问卷 A，引用一次 | 一份答卷：100 | 1 个回答实例 |
| 本人问卷 B，每份答卷引用两次 | 三份答卷：10/11、20/21、30/31 | 6 个回答实例 |
| 另一用户问卷 C，引用共享题目 | 一份答卷：999 | 不进入当前账号的答案统计 |

平均值按全部有效回答计算为 `(100+10+11+20+21+30+31)/7=223/7`，不能对两份问卷的平均值再求等权平均。同一版本在问卷 B 中出现两次，因此一份答卷可以贡献两个回答实例；`surveyCount` 则对问卷去重。另一用户只统计本人问卷中的 999。此例同时检查数据聚合、计数口径和权限边界。

分页测试为文本 v1 保存 22 条回答，以默认 20 条分页读取，三次查询分别返回 20、2、0 条，检查没有遗漏或重复；另两种选择题版本分别保留自己的计数。负偏移、超限页大小、重复参数及不属于该题目的版本均被拒绝。长文本用例 `TestLibraryStatsLargeTextDatasetRemainsPaged` 插入 600 条、每条 10,000 个汉字的回答，检查摘要为 600、首页仅返回 20 条完整原文且 `hasMore=true`。

## 七、运行方法

在项目根目录执行。Go、MongoDB、Make 和 Node.js 的准备方式见 README；带 `-race` 的测试还需要 C 编译工具链。

```sh
make test          # Go 单元测试与 Node 前端测试
make integration   # Go 单元、真实 MongoDB 集成及 race 检测
make verify        # 核心测试、go vet 与构建
```

默认使用 Makefile 管理的 MongoDB，启动前检查服务健康；使用已有数据库时指定连接地址：

```sh
INTEGRATION_MONGO_URI='mongodb://127.0.0.1:27017' make integration
```

浏览器测试先安装锁定依赖和 Chromium，再运行：

```sh
npm ci
npx playwright install chromium
make e2e
```

需要查看核心包覆盖率或单独定位测试时，可以使用：

```sh
go tool cover -func=coverage.out
node tests/frontend/frontend.test.cjs
INTEGRATION_MONGO_URI='mongodb://127.0.0.1:27017' \
  go test -count=1 -race -v ./tests/integration -run '^TestLibrary'
```

`coverage.out` 由成功的 `make integration` 生成。测试中的数据库初始化、版本与统计断言均由仓库代码提供，不需要额外的测试数据文件。
