## 1. 目标

实现可注册登录、创建和分发问卷、按条件跳转填写、保存回答、统计结果的在线问卷系统。

## 2. 实现方案

- 后端：Go 1.26+，标准库 `net/http`；MongoDB Go Driver `v2.9.2`；密码使用 `golang.org/x/crypto/bcrypt`。
- 前端：静态 HTML、CSS、浏览器原生 JavaScript，无前端依赖。
- 分层：`internal/domain` 放置数据模型、校验和跳转；`internal/store` 放置 MongoDB 持久化、索引、JSON Schema 与统计聚合；`internal/web` 放置 HTTP、会话和权限控制。
- 数据库：MongoDB 的 `users`、`surveys`、`responses`、`sessions` 四个集合。题目、选项、规则嵌入问卷；每次回答独立存储。

设计不把所有数据放入单一集合，也不使用关系数据库。一起读取、一起发布的问卷配置嵌入到一份文档；会无限增长、访问模式不同的回答和会话拆开。该模型减少跨集合事务需要，并适合 MongoDB 对嵌套字段和聚合管道的处理。

## 3. MongoDB 设计与完整性

集合及字段见 [design.md](design.md)。系统使用 JSON Schema 强制各集合的必需字段、基础类型、问卷状态枚举和题型枚举；领域层再验证选项引用、长度/范围、规则操作符和跳转方向。

- `users.username` 唯一索引防止重名。
- `responses(surveyId, dedupeKey)` 为 partial unique 索引。禁止重复时，单次 `InsertOne` 与唯一索引共同处理并发竞争；不采用“先查再写”。MongoDB 单文档写入具备原子性。
- `sessions.expiresAt` TTL 索引负责最终清理，但读取仍比较过期时间，避免等待 TTL 监控线程。
- `schemaVersion` 让未来的文档迁移显式可追踪；`revision` 用于草稿乐观锁。

匿名回答省略 `userId`，只保留 SHA-256 去重键以执行“不允许重复”。该键是确定性的假名标识：拥有用户记录的数据库管理员可以枚举用户 ID 并重算哈希来关联回答。因此匿名仅避免在普通响应和统计中直接暴露身份，不提供管理员级别的不可关联性。

## 4. 关键业务逻辑

### 跳转和填写校验

规则由问卷数据定义，而非代码写死。单选、多选和数字题分别支持与题型匹配的操作符。规则按数组顺序匹配，第一条命中即跳转；否则进入下一题；`END` 结束。目标只能在当前题之后，避免环路。

浏览器为了交互会调用“下一题”，但最终提交由服务器从首题重新推导路径，逐题归一化和校验答案，并拒绝包含跳过题目的答案。这避免伪造前端请求绕过必答和跳转规则。

### 问卷状态与并发

问卷从草稿发布后配置、题目和规则冻结；仅允许关闭。每次填写请求以服务端当前时间判断截止时间。保存草稿的更新筛选 `revision`，若其他编辑已保存而本次 revision 过期则返回 `409`，客户端必须重新获取后处理冲突。

### 统计

统计由 responses 实时聚合：先按问卷匹配，再在一个 `$facet` 中同时计算总数和各题结果；每题汇总回答份数和稳定选项 ID 的选择次数，数字题使用 `$avg`；原始答案独立分页读取。创建者能请求全量或指定题目的统计，统计输出不返回用户标识。

## 6. 问题、取舍与解决方式

1. **并发重复提交**：查询后再插入会发生竞争。以 MongoDB partial unique 索引作为最终约束，写入冲突统一翻译为 `409`。
2. **TTL 不立即删除**：TTL 删除异步，故每次会话读取额外检查 `expiresAt`。
3. **前端不能作为安全边界**：所有题目、答案、状态、所有权和截止时间在服务端复验。
4. **匿名与防重复的冲突**：匿名不暴露 `userId`，但仍从已登录用户计算内部去重键；这保留了功能需求并明确了管理员级隐私限制。
5. **可能的未来大数据成本**：当前实时聚合简单且结果新鲜；若回答量显著增加，可在不改变 Stats API 的前提下增加缓存或预聚合。
6. **关闭与正在提交的请求**：提交在写入前再次检查问卷状态和截止时间。一个已经通过这次最终准入检查、但尚在写入中的请求可以在并发关闭之后完成持久化；关闭不是与所有回答写入组成单个事务的硬隔离边界。
7. **统计响应大小（已修复）**：原实现全量聚合原始答案导致单文档16MiB故障；现汇总仅包含有界计数和均值，原文通过独立查询分页返回。深offset和大量题目仍应根据实际负载优化。

## 项目配置归属调整

按后续要求，MongoDB 连接配置改由项目根目录 `.env` 独立持有，运行与测试包装脚本不再读取项目外部 Docker 目录的配置，也不接受外部配置路径变量。旧配置仅在本地进行一次性复制，原 Docker 配置保持不变；实际凭据未写入版本库或文档。`.env` 由 Git 忽略并限制本地文件权限，`.env.example` 只提供无凭据的开发示例。

加载器按脚本位置确定项目根目录，加载 `.env` 的全部键，同时让调用者 shell 中已有值保持优先。`MONGO_URI` 必须存在，`MONGO_DB` 默认 `questionnaire_lab1`，测试连接未单独设置时让 `INTEGRATION_MONGO_URI` 继承 `MONGO_URI`。Go 可执行程序仍保持环境变量驱动，不内置 dotenv 依赖；`make run` 负责开发环境加载，因此部署时可以继续由容器或进程管理器注入配置。

新增的6项Python配置回归已通过，覆盖项目路径定位、全量配置加载、shell优先级、测试连接继承、拒绝把外部配置当作回退来源，以及配置值不作为shell代码执行和错误信息不泄露配置内容。真实MongoDB集成结果单独记录在测试说明中，不以这组配置单元测试替代。
