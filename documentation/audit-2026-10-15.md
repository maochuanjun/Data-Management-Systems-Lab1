## 结论

现有自动化测试和浏览器主流程通过，但额外边界检查确认了 4 类中等优先级（P2）缺陷。此次工作仅排查、复现和记录，没有修复或修改业务代码。审查覆盖领域校验、HTTP 权限与会话、MongoDB 持久化与统计、前端编辑与填写、运行配置和现有测试。

## 已确认的问题

### 1. 保存响应静默覆盖保存期间的新输入

- 位置：`internal/web/static/app.js:123`，按钮禁用逻辑在 `:33`。
- 操作：编辑草稿，点击“保存草稿”，请求尚未完成时继续修改标题或题目。
- 结果：PUT 返回后直接用响应替换整个 `survey` 并重绘，新输入消失，同时提示“草稿已保存”。只有被点击的按钮被禁用，其他输入和操作仍可执行。
- 实测：真实浏览器中延迟 PUT 响应，标题从“保存前标题”改成“保存期间输入的新标题”，响应后回退为“保存前标题”。
- 建议：保存期间锁定编辑器，或跟踪请求之后的本地修改，避免响应覆盖它们；保存与发布操作也应协调。

### 2. 系统允许发布没有合法答案的必答题

- 位置：`internal/domain/logic.go:81-101`；发布处理复用该校验：`internal/web/server.go:372`。
- 配置示例：必答多选题 `maxSelect=0`；必答文本题 `maxLength=0`；必答整数题 `min=0.1, max=0.9`。
- 结果：配置校验成功，但这些题目没有任何合法答案。若实际路径经过该题，填写者无法完成问卷；发布后也无法编辑修正。
- 实测：临时领域测试确认上述三种配置被接受；真实 HTTP 创建必答 `maxLength=0` 文本题返回 201，发布返回 200。
- 建议：发布前校验必答约束是否存在可满足的值，包括零上限、整数区间和安全数值范围。

### 3. 合法题目 ID `__proto__` 导致前端答案丢失

- 位置：`internal/web/static/app.js:159`、`:176`、`:194`；服务端 ID 校验：`internal/domain/logic.go:15`、`:31`。
- 操作：通过 API 创建并发布 ID 为 `__proto__` 的必答文本题，打开填写页面并填写、提交。
- 原因：`answers` 是普通对象。读取该键会读取继承属性，赋值触发原型 setter，JSON 序列化无法得到预期答案字段。
- 实测：真实 API 创建 201、发布 200；文本框初始为 `[object Object]`；填写后最终提交缺少答案并返回“题目 __proto__: 必答题不能为空”。前端最小 harness 还确认最终提交载荷为 `answers:{}`。
- 影响边界：当前页面自动生成的题目 ID 不会生成该值，但 API 明确接受该值，API 创建的合法问卷会受到影响。
- 建议：使用 `Object.create(null)` 存储答案，并只读取自己的属性；补充特殊键回归测试。

### 4. 回答累计增大后统计聚合超过 BSON 文档限制

- 位置：`internal/store/mongo.go:232`、`:243`；HTTP 错误处理：`internal/web/server.go:539`。
- 原因：所有题目的原始答案通过 `$push` 聚合，再放进单个 `$facet` 结果文档，体积随回答数持续增长。
- 实测：一道文本题，每份回答 10,000 个汉字，全部通过领域校验。1 份回答统计正常；600 份时统计报 `BSONObjectTooLarge: BSONObj size: 18005975`，超过 16 MiB。HTTP 会将其转换为 500，单题查询也不能规避该题自身超过上限的情况。
- 影响：数据仍能提交，但统计无法读取；容量门槛取决于题数和答案长度，600 份仅为本次复现样例。
- 建议：聚合只返回计数、选项次数和平均值；文本与原始答案使用分页接口，避免构造无限增长的单文档。
- MongoDB 官方限制说明：[Aggregation $facet](https://www.mongodb.com/docs/manual/reference/operator/aggregation/facet/)。

## 后续修复与回归（同日）

用户随后要求“尝试修复，并补充回归测试”，上述四类缺陷已修复；前文保留为修复前的审计记录。

- 保存和发布期间禁用整个编辑器并阻止重复请求；失败时恢复编辑并保留内容。
- 必答题增加可满足性检查，拒绝零长度/零选择上限、无整数区间以及完全超出安全数字范围的配置；可选题仍可跳过。
- 答案字典使用无原型对象，支持合法 ID `__proto__`、`constructor`、`toString`。
- 统计仅聚合有界汇总，原始答案稳定分页；页面支持单题上一页/下一页，并处理失败重试、切换筛选及离开页面后的失效响应。

永久回归测试位于 `internal/domain/logic_test.go`、`internal/store/mongo_test.go`、`internal/web/integration_test.go` 和 `tests/frontend.test.cjs`。领域与容量测试均先在旧代码上复现失败，再验证修复通过；前端首批20项在旧代码上16项失败，最终21项全部通过。`python3 scripts/with-local-mongo.py make integration` 最终通过，Go测试启用 `-race`，真实MongoDB集成未跳过。跨包语句覆盖率为82.1%；静态检查与编译通过。
