# MongoDB 数据库设计与关键逻辑

系统使用 Go 提供 HTTP 服务，业务数据全部保存在 MongoDB，前端采用原生 HTML、CSS 和 JavaScript。数据库设计围绕问卷配置、独立答卷、可复用题目和不可变版本展开。本文说明第一阶段设计如何继续承担原有业务，以及第二阶段为什么需要增加题目来源、版本和题库。

## 一、原有设计与调整理由

### 1. 第一阶段的设计

第一阶段使用 `users`、`sessions`、`surveys`、`responses` 四个集合。题目、选项、校验条件和跳转规则嵌入 `surveys.questions`，一次读取即可取得一份完整问卷；每次提交独立写入 `responses`，通过 `surveyId` 关联问卷。问卷发布后不允许修改题目配置，答卷中的稳定题目 ID 因而仍能对应原来的含义。

这个设计适合以一份问卷为单位的编辑、填写和统计。答卷不嵌入问卷，避免热门问卷文档不断增长，也避免多人提交集中修改同一文档。题目 ID、`revision`、`schemaVersion` 和分层代码为后续扩展保留了基础。

### 2. 新需求带来的问题

| 新的使用方式 | 原设计的不足 | 调整方式 |
| --- | --- | --- |
| 保存题目并用于多份问卷 | 题目仅属于某份问卷，复制后无法识别共同来源 | 增加独立题目实体，在问卷快照中保存来源题目和来源版本 |
| 共享题目给其他账号 | 原权限仅按问卷创建者判断，不能表达题目授权 | 将题目归属和共享名单放入 `question_templates` |
| 修改、分支和恢复历史题目 | 直接覆盖一份公共内容会改变旧问卷含义，简单复制又缺少历史关系 | 用 `question_versions` 追加不可变内容，记录父版本和恢复来源 |
| 整理题库并选择更新版本 | 问卷内数组不适合作为独立的题库目录 | 用 `question_banks.versionIds` 显式固定具体版本 |
| 查看使用情况与跨问卷回答 | 原统计以 `surveyId` 为入口，相同标题不能证明是同一道题 | 按来源找到问卷内题目实例，再用局部 ID 读取答卷并按版本汇总 |

第二阶段保留原四个集合和答卷结构，增加三个集合及问卷题目的两个可选来源字段。原来的填写、跳转、答案校验和单卷统计仍读取问卷自己的内容；新增功能使用来源信息建立复用与统计关系。

### 3. 程序组织

| 层次 | 原有职责 | 扩展后的职责 |
| --- | --- | --- |
| `internal/domain` | 问卷模型、配置校验、答案校验和跳转 | 增加题目、版本、题库模型，可复用内容校验及来源内容比较 |
| `internal/store` | MongoDB 初始化、问卷和答卷读写、单卷统计 | 增加题库集合与索引、版本分配、共享修订、使用情况及跨问卷聚合 |
| `internal/web` | 身份校验、问卷权限、HTTP 接口 | 增加题目读取与作者权限、共享、版本、题库接口；保存问卷时校验来源快照 |
| `internal/web/static` | 创建、填写和统计页面 | 增加选题、版本历史、共享、题库和跨问卷统计，并统一草稿及异步响应保护 |
| `tests` | 领域、数据库、前端和浏览器测试 | 在原目录中增加复用、版本、权限、并发、兼容及交互回归 |

新增领域、存储和 HTTP 逻辑分别位于各层的 `library.go`，没有用另一套系统替换原有问卷流程。

## 二、集合、字段与关联

### 1. 七个集合

| 集合 | 主要字段 | 设计考虑 |
| --- | --- | --- |
| `users` | `_id`、`username`、`passwordHash`、`createdAt` | 账号长期保存，用户名唯一，密码保存 bcrypt 哈希 |
| `sessions` | `_id`、`userId`、`expiresAt` | 令牌哈希作为文档 ID，独立控制退出和到期 |
| `surveys` | `_id`、`ownerId`、`title`、`description`、`status`、`archived`、`deadline`、`allowAnonymous`、`allowRepeat`、`questions`、`revision`、`schemaVersion`、`createdAt` | 保留完整问卷配置和题目快照，发布后配置冻结 |
| `responses` | `_id`、`surveyId`、`answers`、`path`、`anonymous`、可选 `userId`、必要时的 `dedupeKey`、`schemaVersion`、`submittedAt` | 每次合法提交一条记录，答案按问卷内局部题目 ID 保存 |
| `question_templates` | `_id`、`ownerId`、`sharedWith`、`sharingRevision`、`nextVersion`、`ready`、`createdAt` | 表示同一道可复用题目的身份、权限和版本号分配状态 |
| `question_versions` | `_id`、`questionId`、`version`、`parentVersionId`、`restoredFromVersionId`、`question`、`note`、`createdAt` | 保存确定的题型、标题、必答、选项及校验约束，保留派生和恢复关系 |
| `question_banks` | `_id`、`ownerId`、`name`、`description`、`versionIds`、`revision`、`createdAt` | 个人题库组织具体版本，更新时显式替换固定项 |

接口中的 `latestVersion` 和 `sharedUsernames` 是读取时装配的结果，不是另存一份可修改内容。`ready` 用于内部判断题目是否创建完整，不作为页面业务字段返回。

### 2. 三种题目标识

| 标识 | 作用 | 示例 |
| --- | --- | --- |
| 题目族 ID | 判断哪些版本属于同一道可复用题目 | 年龄题的 v1、v2、v3 共享同一个 `questionId` |
| 版本 ID | 指向一份确定、不可覆盖的内容 | 范围 0–120 的 v1 和范围 0–150 的 v2 分别拥有版本 ID |
| 问卷内局部题目 ID | 标识该题在某份问卷中的一次出现 | 同一版本在问卷中出现两次，分别使用 `age_first`、`age_second` |

引用后的问卷题目仍保存完整内容，只增加可选的 `sourceQuestionId` 和 `sourceVersionId`。例如：

~~~json
{
  "id": "age_first",
  "sourceQuestionId": "age_template",
  "sourceVersionId": "age_v1",
  "title": "年龄",
  "type": "fill",
  "fillType": "number",
  "required": true,
  "options": [],
  "validation": {"min": 0, "max": 120, "integer": true},
  "rules": []
}
~~~

答卷继续保存 `{"answers":{"age_first":21},"path":["age_first"]}`。因此，统计能够按来源判断共同题目，又能区分同卷中的多次出现，不需要改写第一阶段的答案键。

### 3. 快照与引用的分工

可复用版本供选题、历史查询和来源识别使用，问卷内快照供本问卷的展示、校验、跳转和历史答案解释使用。快照产生一定冗余，但使已有问卷不依赖题库的最新状态。派生版本、恢复历史、撤销共享和删除题库都不会自动替换问卷中的内容。

保存问卷时，来源题目、版本和题型、标题、选项、必答、约束必须对应。`QuestionContentEqual()` 只排除局部 ID、来源字段及问卷局部跳转规则，并处理等价的历史填空表示。不能只提供一个有效版本 ID，再随意修改其快照内容。需要独立编辑时，草稿可同时移除两项来源字段，之后按独立题目管理，不再计入原题目的跨问卷统计。

跳转规则引用当前问卷的局部题目 ID，因此留在 `surveys.questions[].rules`，不放入可复用内容。题目版本的内部 `id` 规范为 `template`；选入问卷时再分配局部 ID。

## 三、为什么采用这种 MongoDB 模型

第一阶段最常见的访问是读取一份完整问卷，第二阶段增加的访问则是检索题目、选择版本和汇总共同来源的回答。根据访问方式分别采用配置嵌入、答卷引用、版本独立保存，比把所有数据放入一个集合更便于控制文档增长和权限。

关系数据库也能通过题目、版本、问卷、选项和关联表完成这些功能，并具有外键和 JOIN 能力。本项目按课程要求使用 MongoDB，没有把每个嵌套实体机械拆成集合：共同读取的题目配置仍放在问卷文档中，独立管理的题目权限与历史版本再单独建模。跨集合的来源、授权和版本归属由应用校验，不能依赖关系数据库式外键。

BSON 能表达问卷中的嵌套数组和多种答案值。聚合管道负责计数、求平均和数值分布；唯一索引、TTL 索引和 JSON Schema 提供持久化约束。题目版本与问卷快照有意保留少量重复内容，其目的是固定历史语义，不让每次填写都临时读取最新题目。

## 四、索引与约束

| 索引 | 用途 |
| --- | --- |
| `users(username)` 唯一 | 阻止同名账号 |
| `sessions(expiresAt)` TTL | 清理到期会话；读取时仍检查到期时间 |
| `surveys(ownerId, createdAt)` | 按创建者读取问卷列表 |
| `responses(surveyId, dedupeKey)` 部分唯一 | 禁止重复填写时，限制同一账号成功写入的答卷数 |
| `responses(surveyId, submittedAt, _id)` | 按问卷过滤并稳定分页 |
| `question_templates(ownerId, ready, createdAt)` | 查询本人已就绪题目 |
| `question_templates(sharedWith, ready)` | 查询获共享的题目 |
| `question_versions(questionId, version)` 唯一 | 限制同一题目版本号重复，并支持历史及最新版本读取 |
| `question_banks(ownerId, createdAt)` | 查询个人题库 |
| `surveys(ownerId, questions.sourceQuestionId)` | 查找本人引用某题的问卷 |
| `surveys(questions.sourceQuestionId, questions.sourceVersionId)` | 查询题目来源及具体版本的引用 |

基础集合的 Schema 和索引在 `internal/store/mongo.go`，题库扩展在 `internal/store/library.go`。JSON Schema 检查必要字段、BSON 类型、状态和题型枚举；跨字段规则、前向跳转、来源一致性、题库版本重复及授权由 Go 检查。

问卷最多 100 道题；题目与选项 ID 由领域层检查有效性和唯一性。新配置的单选、多选标签去除首尾 Unicode 空白后不能相同，比较区分大小写且不改写存储文字。已有已发布快照的填写仍按稳定选项 ID 校验，不因新增标签规则失效。

## 五、版本、共享与题库管理

### 1. 不可变版本与历史恢复

保存修改使用插入新版本，不提供覆盖历史版本内容的业务接口。`parentVersionId` 记录派生基线；`restoredFromVersionId` 记录恢复内容来自哪里，两者含义不同。

| 版本 | 操作 | 父版本 | 恢复来源 |
| --- | --- | --- | --- |
| v1 | 新建题目 | 无 | 无 |
| v2 | 从 v1 修改 | v1 | 无 |
| v3 | 再从 v1 创建另一分支 | v1 | 无 |
| v4 | 当前最新为 v3 时恢复 v1 | v3 | v1 |

v4 复制 v1 的内容，v1–v3 仍存在。恢复不会移动旧问卷的来源引用，也不会删除较新的版本。历史版本有旧重复标签时仍可忠实恢复；如果恢复内容用于新的草稿保存或发布，仍须先修正为满足当前配置规则的版本。

### 2. 创建过程与并发版本号

题目创建依次写入 `ready=false` 的题目族、v1，再设 `ready=true`。普通读取只返回已就绪题目。若写入中断，后续 `Init()` 检查是否存在完整 v1：有 v1 才恢复可见，没有 v1 继续隐藏。它是针对两次文档写入的恢复措施，不等同于跨文档事务。

派生版本通过原子 `$inc` 分配编号，再插入版本文档，唯一索引限制编号重复。分配后插入失败可能留下空号，因此“最新版本”按实际保存的最高版本查询，不能仅依据 `nextVersion` 推断存在某个版本。并发派生可拥有相同父版本，但分配不同编号。

### 3. 共享与使用情况

题目作者按注册用户名授权，数据库保存账号 ID。共享接收者可读取和选用该题的版本，不能替作者修改版本或共享名单。作者可见共享名单，接收者不获取其他接收者名单。

共享只授权题目复用。使用情况显示本人问卷的标题、状态、局部题目和来源版本；作者另外看到全体用户的引用问卷总数及出现次数，不返回他人问卷名称、ID 或答案。跨问卷答案统计仍只纳入当前账号自己创建的问卷，这是项目已明确的权限范围。

撤销共享阻止后续读取和新增引用，旧已发布问卷仍可按快照填写和查询单卷统计。草稿保存时，仅允许局部 ID、来源及内容均与原快照一致的既有引用继续保留，保存和发布还须通过当前配置校验。旧题库固定项可以保留，但保存了版本 ID 并不产生新的访问权限。

### 4. 三类版本与修订号

| 字段 | 管理对象 | 冲突处理 |
| --- | --- | --- |
| `question_versions.version` | 题目内容历史 | 追加不可变版本，保留父版本，不覆盖旧内容 |
| `sharingRevision` | 题目的共享名单 | 保存时比较当前修订号，成功后递增；过期名单返回 409 |
| 问卷或题库的 `revision` | 可编辑配置和状态 | 按修订号条件更新，阻止旧页面覆盖新状态 |

`schemaVersion` 表示持久化结构版本，不参与上述内容历史或编辑锁。共享名单和内容版本使用不同机制，避免一次编辑内容无意覆盖授权。共享保存遇到 409 后需要重新读取并核对，不自动重试旧名单。

### 5. 个人题库固定版本

题库按 `versionIds` 保存具体版本，支持添加、移除和显式替换。新版本出现时，题库和已有问卷不会自动更新。删除题库只删除组织容器，不删除题目版本、问卷或答卷。题库由当前账号管理，共享发生在题目层，没有额外的团队题库授权机制。

## 六、问卷、跳转与提交

问卷沿用 `draft`、`published`、`closed` 状态，并以 `archived` 表示归档。只有未归档草稿可以修改和发布；已发布配置冻结。关闭、截止或归档后停止正常收集，恢复归档不自动重新开启。删除只适用于没有答卷的草稿，重新开启保留历史答卷。

单选支持 `eq`，多选支持 `contains`、`contains_all`，数字填空支持 `eq`、`gt`、`gte`、`lt`、`lte`。多条规则按顺序使用第一条命中结果，没有命中则进入下一题。目标只能是后续题目或 `END`，从配置上禁止循环。

配置保存、逐题 `/next` 和最终提交分别校验。单选必须引用存在的选项，多选不允许重复 ID 且满足数量范围；文本按 Unicode 码点检查长度；数字检查有限值、上下界和整数要求，0 是合法数值。精确选择数量通过相同的最小值和最大值表达。`ValidateSubmission()` 从首题重算实际路径，拒绝不存在或已跳过题目的答案。

所有填写者先登录。只有问卷允许匿名且本次选择匿名时，新答卷才省略 `userId`；匿名与实名在禁止重复时共用 `digest(surveyId + ":" + userId)` 去重键。公开读取额外返回当前账号的 `submissionBlocked`，便于在首题前提示已提交；该预检不返回答卷内容，也不能替代最终唯一索引防重。

最终答卷请求体上限为 16 MiB，其他 JSON 请求保持 1 MiB。限制按传输字节计算，业务上仍限制题目数及每个文本答案最多 10,000 个 Unicode 码点。超过请求容量返回 413，格式或字段不合法返回 400。

## 七、统计的扩展与口径

### 1. 单卷统计

单卷统计按 `surveyId` 查询已保存答卷，计算 `totalResponses`、各题 `answered`、选项次数和数字平均值。文本、数字原始内容独立分页，不把所有长文本聚合到一个结果中。指定 `questionId` 只返回该题，整卷提交份数仍保留。

缺失、`null` 及被跳过答案不计 `answered`；合法空字符串、空多选数组和数字 0 计入。空数组不增加选项次数，0 参加数字平均值。允许重复提交时计数代表答卷或选择次数，不是去重人数。

### 2. 跨问卷统计

跨问卷查询先按当前账号的 `ownerId` 筛选问卷，再展开符合 `sourceQuestionId` 和可选 `sourceVersionId` 的题目实例，通过 `surveyId` 关联答卷，使用局部题目 ID 读取 `answers`。结果按不可变版本分别统计，避免修改题型或选项含义后混算。

`totalAnswers` 统计回答的题目实例数，`surveyCount` 统计实际贡献回答的不同问卷数。同一版本在同卷出现两次，一份答卷可以贡献两个实例。数字平均值直接基于全部有效数值计算，不先求每份问卷的均值再平均；`$bucketAuto` 提供最多 10 桶的自适应数值分布。

例如，本人问卷 A 引用一次，提交 100；问卷 B 引用两次，三份答卷依次提交 10/11、20/21、30/31。结果为 7 个回答实例、2 份贡献问卷，均值 `223/7`。另一用户问卷中的 999 不进入本人答案统计。使用情况另统计所有现存引用，包括尚未回答的草稿，因此不能把使用问卷数与贡献回答的问卷数混为一谈。

全部版本视图只返回摘要；选择具体版本后返回分页原文，每页默认 20 条、最多 50 条。按提交时间、答卷 ID、问卷 ID、局部题目 ID 稳定排序，多读取一条判断下一页。运行基准为 MongoDB 8.0；相关聚合与动态答案字段读取集中在 `internal/store/library.go`。

## 八、旧数据与页面行为的延续

| 兼容对象 | 处理方式 |
| --- | --- |
| 没有来源字段的旧问卷 | 继续按独立题目处理，不根据相同标题补造共同来源 |
| 第一阶段答卷 | 保留原答案键、路径和统计方式；另存旧题目到题库不会自动迁移旧回答 |
| 旧 `text/number` 题型 | 服务端仍可读取、校验及接受旧式问卷写入；前端统一为 `fill + fillType`，题目版本接口规范化新版本内容 |
| 缺少 `sharingRevision` 的历史题目 | 按 0 读取，首次成功保存共享名单时原子递增 |
| 缺少去重键的历史答卷 | 对可识别账号的禁止重复问卷补齐辅助键，保留全部原记录；已有有效键优先 |
| 旧已发布重复标签题目 | 按原选项 ID 继续填写；历史恢复保留原内容，新配置保存和发布执行严格标签校验 |

历史去重回填不删除重复旧答卷，也不改写答案、匿名标志和提交时间。没有身份信息且没有去重键的旧匿名记录无法可靠关联账号，不猜测其填写者。初始化允许重复执行，真实读取或写入失败会返回错误。

前端分别保存原始输入草稿和当前路径上已校验的答案。返回上一题可恢复文本、数值原串和选项；改变分支后，概览与最终请求只使用有效路径。概览显示题号和选项文字，区分主动跳过、合法空答案和数字 0。

编辑离开、浏览器后退和刷新检查未保存内容，取消后保留输入；保存成功更新比较基准，等价截止时刻不误提示。退出请求期间阻止新编辑，失败后恢复。规则区和限制区保留展开状态。新增问卷、题目、题库以及统计等异步操作还检查发起页面或查询代次，迟到响应不能改写新页面；忽略响应不表示撤销已经发出的写请求。

## 九、验证与当前边界

旧样例位于 `tests/fixtures/v1`，领域、数据库、前端和真实浏览器回归均沿用 `tests/`。兼容验证读取旧用户、问卷和答卷，重新执行编辑、发布、填写与统计，并比较原记录是否保留；题库测试另外检查旧版本与旧快照不变、撤销共享、来源防伪、并发编号和加权统计。步骤、固定输入与结果集中在 [测试用例与结果](testing.md)。

当前列表和完整版本历史没有分页，大量题目或版本会增加查询成本。统计摘要与原文分页不是跨请求一致性快照，关闭问卷与已进入写入阶段的提交也没有组成跨文档事务。创建恢复机制可能保留没有 v1 的隐藏记录；页面草稿保护没有提供跨会话自动保存。后续扩展仍需保持历史内容、显式版本选择和答案权限不变。
