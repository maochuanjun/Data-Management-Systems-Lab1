# 测试整理与阶段一验收计划

本次保留已有功能和另一窗口的修复，统一测试入口，为后续需求变更提供可重复执行的行为基线。

1. 整理前先执行现有快速测试、真实 MongoDB 集成与容量回归、静态检查和构建；保留修复为独立 Git 提交。此项已通过，前端原有 21 项回归通过。
2. 按用户更正，将测试统一至已有的 `tests/unit`、`tests/integration`、`tests/frontend`，真实浏览器验收放在 `tests/e2e`。通过公开领域/HTTP/存储接口测试，不为测试导出私有函数或数据库字段。数据库测试使用随机独立数据库并清理。
3. 补齐恰选两项、不同用户并发、版本 1 固定数据兼容性用例。保留同账号并发去重和长文本容量回归。
4. 修复审查发现的翻页后汇总不更新问题，先增加失败回归；区分提交份数和独立人数。
5. 保留轻量前端回归，并添加真实浏览器的可重复端到端验收。测试依赖与运行范围写清楚，数据库验收入口在未配置 URI 时应失败，避免把跳过误认为通过。
6. 更新使用指南、需求验收映射、测试分层和第二阶段扩展约定。最后执行整理后的完整回归、浏览器验收、构建与静态检查，保存 Git 记录。

停止条件：原始需求均有实现与验证证据；没有遗留测试散落在业务目录；已有数据可读；真实 MongoDB 回归和新增验收通过；文档与当前接口一致。

执行结果：以上步骤已完成。真实 MongoDB、旧数据兼容、不同用户并发、22项前端及5个真实浏览器场景通过，静态检查和构建通过；核心包覆盖率85.6%。详细输入输出与边界见 [测试记录](testing.md)。
