# 第二阶段需求分析与设计调整

第二阶段在第一阶段问卷系统上增加题目的保存、共享、版本管理、题库和跨问卷统计。调整的核心是把题目作为可以独立管理的对象，同时保留问卷内的完整题目快照，使已发布问卷和已有答卷继续具有确定的含义。

## 一、第一阶段的设计是什么

第一阶段使用 `users`、`sessions`、`surveys`、`responses` 四个集合。`surveys.questions` 内嵌题目、选项、校验条件和跳转规则，一次读取即可取得完整配置；`responses.answers` 以问卷内的题目 ID 为键，另存服务器计算的实际作答路径。问卷发布后冻结题目配置，提交接口根据冻结配置重新校验答案，单卷统计只向创建者开放。

这一设计适合以单份问卷为中心的功能：创建、编辑、发布、填写、条件跳转和单卷统计均可直接围绕问卷文档完成。文本与数字填空、必答、匿名及重复填写设置、截止时间、归档与重新开启等功能都有独立的规则，不需要先查询题库。

## 二、新需求带来了哪些问题

题目嵌入问卷后，不同问卷中的相似题目只是独立副本，没有共同的身份、作者和共享权限。直接复制题面可以再次使用，但不能可靠判断来源，也无法知道哪些问卷采用了同一个历史版本。题目名称相同不代表含义相同，名称改变也不代表它成为无关的新题。

如果让问卷只保存一个指向最新题目的引用，题库更新后旧问卷的题面和答案解释就可能改变。选项 ID、数字范围、题型发生变化时，旧答案不能直接按新配置统计。历史恢复、多分支并存和版本选择也要求保留不可变内容，而不是反复覆盖同一条题目记录。

因此，原有问卷和答卷结构继续承担填写业务，新增独立的题目身份、不可变版本和个人题库。在问卷快照上记录明确来源，把“内容稳定”和“能够追溯”同时保留下来。

## 三、八项需求如何落实

| 第二阶段要求 | 数据与设计调整 | 程序行为与验证重点 |
| --- | --- | --- |
| 保存并复用题目 | `question_templates` 保存身份和作者，`question_versions` 保存具体内容；问卷保存完整快照及来源 ID。 | 可新建可复用题目，也可从问卷题目另存；选题后生成问卷内局部 ID。同一版本可用于多份问卷，并可在同一问卷重复出现。 |
| 共享给指定用户 | 题目身份保存 `sharedWith`；共享名单使用独立 `sharingRevision`。 | 作者按用户名授权；接收者可读和引用，不能替作者修改或继续授权。过期共享修订号返回冲突，防止旧页面重新授予已撤销的权限。 |
| 已发布问卷保持不变，修改形成新内容 | 版本只新增，问卷快照固定；发布后的问卷禁止修改题目配置。 | 作者修改题目时新增版本记录。已有问卷继续使用原版本；需要完全独立管理时，可另存为新题目。验证修改不会改变旧题面、选项和答案。 |
| 查看历史、追踪来源并恢复 | 版本保存 `parentVersionId` 和 `restoredFromVersionId`，问卷保存 `sourceQuestionId/sourceVersionId`。 | 历史版本可读；恢复将历史内容复制为新版本，记录父版本及恢复来源，保留中间版本与已有引用。 |
| 多版本及分支并存 | 同一题目下保存多个版本，编号递增，父子关系单独记录。 | 创建版本时可指定任意历史基线，不要求从最新版修改；旧版本、主分支和其他分支均可继续被选择。 |
| 查看哪些问卷使用了题目 | 根据问卷快照中的来源检索当前引用。 | 返回本人问卷的引用明细；题目作者另外看到全局引用总量。分别统计不同问卷数和题目出现次数，不披露其他用户的问卷 ID、标题或答案。 |
| 管理题库并更新版本 | `question_banks.versionIds` 固定具体版本，`revision` 保护并发更新。 | 创建、修改和删除个人题库，添加、移除或显式替换固定版本；新版本产生后由用户选择是否更新，已有问卷不自动替换。 |
| 跨问卷查看单题答案与分布 | 以来源题目和具体版本关联本人问卷中的题目实例与答卷。 | 分版本显示回答数、选项次数、数字均值与分布，文本及数字答案分页读取。验证同版本重复出现、不同版本隔离、零值和权限范围。 |

这里的“跨问卷”沿用当前权限约定，只归并当前用户创建的多份问卷。题目共享授予复用权，问卷答案的读取权仍属于问卷创建者。题目作者能看到全局引用数量，但不能据此读取其他作者的问卷和答卷。

## 四、数据结构如何变化

集合由四个增加到七个，原有四个集合继续使用。`question_templates` 管理作者、共享名单和版本编号；`question_versions` 保存不可变题目内容及来源关系；`question_banks` 组织用户选定的版本。问卷题目新增可选的 `sourceQuestionId` 和 `sourceVersionId`，答卷结构保持原有含义。

三个题目标识各有用途：题目身份 ID 表示“哪一道可复用题目”，版本 ID 表示“采用哪次确定的内容”，问卷内题目 ID 表示“本问卷中的哪一次出现”。答卷继续以第三种 ID 为键。同一版本出现两次时，两个局部 ID 对应两组答案，跨问卷统计再根据来源将它们归入同一版本。

可复用内容不包含问卷跳转规则。跳转目标依赖本问卷的局部 ID，应由当前问卷编排。保存引用时，服务器检查来源成对存在、版本归属正确、快照内容一致，并检查新增引用的读取权限，防止任意题面冒用其他来源。

`version` 是不可变内容的版本号，问卷与题库的 `revision` 是并发修改修订号，`sharingRevision` 是权限名单修订号。三者独立，修改共享名单不会改变题目内容版本。版本编号由原子递增分配，后续插入失败可留下空号；最新版本以实际保存的记录为准，父子关系以来源字段为准。

## 五、程序如何调整

领域层在原有题型、校验和跳转逻辑之外，增加可复用题目、版本、题库及来源一致性校验。存储层保留用户、会话、问卷和答卷操作，增加版本写入、共享更新、题库修订、引用查询及跨问卷聚合，并为新查询建立索引。

HTTP 层继续提供原有问卷和填写接口，增加 `/api/questions`、`/api/question-versions`、`/api/question-banks` 等接口。创建和保存问卷时检查来源，填写时仍直接使用问卷快照。跨问卷统计先筛选当前用户的来源题目实例，再按局部 ID 取出答案，按版本分别计算，避免将不同含义的答案合并。

页面增加题库、版本、共享、使用情况和跨问卷统计入口，问卷编辑页增加选题与另存功能。未保存修改离开前提示；填写页保留页面内回退输入，提交前展示实际路径的答案概览。页面切换和查询切换后，迟到响应不能覆盖新页面状态；首页新建问卷完成时也先确认当前页面仍属于该请求，再决定是否跳转编辑页。

## 六、兼容性问题与处理

旧问卷没有来源字段时仍作为独立题目使用，旧答卷不补造来源、不重写答案键。将旧题另存为可复用题目会创建新的身份，过去的提交不会自动成为该新身份的统计数据。服务端继续支持历史 `type=text/number`，前端和新可复用内容采用 `fill + fillType`。

共享撤销后，已经保存的问卷快照继续可用；已有引用在局部 ID、来源和内容保持一致时可以保留，但不能再新增无权读取的引用。已有题库固定项也可保留，读取版本和新增引用仍执行当前权限检查。

新草稿保存、发布以及新版本编辑要求选项文字去除首尾空白后不重复。历史已发布问卷仍依据稳定选项 ID 接收回答；恢复历史版本忠实保留旧内容。含重复文字的历史内容如果用于新的草稿，必须先派生修正版或转成独立题目修改。这区分了历史数据的原样解释与新配置的合法性。

旧共享数据缺少 `sharingRevision` 时按 0 处理，首次修改写入 1。历史答卷中能够识别账号的记录可补充防重标记，保留全部历史答卷；缺少身份信息的旧匿名记录无法推断原账号，系统不虚构关联。

## 七、如何保证旧功能仍然可用

验证同时覆盖第一阶段的问卷创建与状态流转、所有题型与约束、条件跳转、匿名及禁止重复、截止时间和单卷统计，以及第二阶段的八项功能。旧数据兼容和权限变化分别构造场景，检查保留来源、撤销共享、历史恢复、分支选择和跨版本统计；并发场景检查问卷、题库和共享名单的修订号冲突。

领域和 HTTP 测试验证规则与接口，真实 MongoDB 集成测试验证唯一索引、原子条件更新和聚合结果，前端回归及浏览器测试验证页面操作、未保存提示和迟到响应处理。测试用例和实测结果集中说明在 [测试用例与结果](testing.md)，数据库结构见 [数据库与核心逻辑设计](design.md)，请求与响应见 [HTTP API 说明](api.md)。

当前实现使用普通 MongoDB 单文档原子更新和唯一索引，不依赖多文档事务。跨问卷答案分页不保证跨请求的同一时点快照，关闭问卷与正在进行的答卷写入之间也仍存在并发窗口；页面内输入保留不等于刷新后可恢复的持久化草稿。这些边界不改变已有数据的解释和权限范围。
