# 初始版本需求说明


## 目标与边界

本系统实现一个在线问卷产品：注册用户创建、编辑、发布和关闭问卷；任何填写者均须先登录，再通过分享链接填写；创建者查看自动汇总的统计结果。

初始版本使用 Go 1.26+、MongoDB 和浏览器原生 JavaScript；不使用关系数据库、现成问卷系统或前端框架。页面以功能可用和可访问为目标，不追求复杂视觉效果。

## 角色与权限

| 角色 | 可执行操作 |
| --- | --- |
| 未登录访客 | 访问静态页面；打开分享链接后被要求登录 |
| 登录用户 | 注册后的登录、填写已发布且未到期的问卷；可选择匿名提交（若问卷允许） |
| 问卷创建者 | 创建、列出和读取自己的问卷；草稿编辑、发布、关闭；查看自己的统计 |

“匿名”只表示结果和统计中不展示填写者 `userId`。所有填写者仍须登录；当关闭重复提交时，服务端仍按照登录用户去重。

## 功能需求

1. 账号：注册时保存用户名、bcrypt 密码哈希与注册时间；登录、登出和当前用户查询均使用服务端会话。
2. 问卷：创建者填写标题、说明、是否允许匿名、是否允许重复、截止时间和题目。仅创建者能看到自己创建的问卷和统计。
3. 生命周期：`draft → published → closed`。仅草稿可编辑；发布时冻结问卷配置和题目；已发布问卷只能关闭，不能回到草稿。推进题目与提交时检查截止时间，过期问卷不可再填写；读取公开元数据可用于展示关闭或到期提示。
4. 题型：单选、多选、文本填空、数字填空。支持必答、多选最少/最多选择数、文本最少/最多字符数、数字最小/最大值和整数限制。
5. 跳转：规则存储在题目中。单选按 `eq`，多选按 `contains` 或 `contains_all`，数字按 `eq/gt/gte/lt/lte` 判断。规则按书写顺序取第一条命中项；未命中进入下一题；`END` 结束。目标只能为后续题目或 `END`，所以不会形成循环。
6. 提交：服务端重算实际作答路径、校验每一题并拒绝被跳过题目的伪造答案。单份回答作为一个 MongoDB 文档写入；不同用户可并发提交。
7. 统计：创建者可看整个问卷或单题。单选/多选显示每个选项次数和已回答人数；文本显示填写内容；数字额外显示平均值。统计从 responses 聚合生成，不预先复制统计数据。

## 关键约束与验收

- 标识符为稳定字符串：问卷、用户、会话和回答均使用字符串 `_id`；题目和选项使用在问卷内稳定的字符串 ID。显示文字可以修改，但规则通过 ID 引用。
- 文档携带 `schemaVersion`，草稿携带 `revision`。编辑草稿必须携带当前 revision；不一致返回冲突，不覆盖他人的新修改。
- 不允许重复提交时，responses 用唯一索引保证同一问卷、同一登录用户至多一份回答。匿名回答不写 `userId`，而写入 `SHA-256(surveyID + ":" + userID)` 的内部 `dedupeKey`。该键是确定性的假名标识；拥有用户记录的数据库管理员可重算它并关联回答，因此不提供管理员级别的不可关联性。
- MongoDB JSON Schema 负责基本字段类型和必需字段；领域层负责题目互相引用、跳转方向、值域与作答路径等跨字段语义。
- API 返回 JSON；参数或业务校验失败为 `400`，未登录为 `401`，资源不存在或非所有者访问私有问卷为 `404`，修订冲突/重复提交/非法状态迁移为 `409`，未预期数据库错误为 `500`。

## 后续演进预留

不把规则写死在页面或后端分支中；题目、选项和规则均随问卷文档保存。`schemaVersion` 和 `revision` 为后续迁移、兼容旧数据和并发编辑提供边界。后续版本应基于本结构增量修改，并保留变更与兼容策略。
